# issue-3 — 7f21e5e7 record

## What was done

Changed only `cmd_board` in `tools/otr.py` (14 insertions, 2 deletions),
as approved in the proposal:

1. Branches are enumerated with
   `git for-each-ref --format=%(refname:short) refs/heads/issue-*/*` instead
   of `git branch --list`, whose `* `/`+ ` worktree markers survived
   `.strip()` and hid every checked-out subagent branch.
2. A branch counts as merged only when its record is on main and
   `git merge-base --is-ancestor BRANCH main` succeeds; such branches keep
   the existing `landed` line.
3. For every other branch the record is read from the branch tip with
   `git show BRANCH:docs/issue-N/reports/HEX.md` (no checkout); empty output
   renders as `no record`, otherwise `type loop_state` via the linter's
   `parse_frontmatter`.
4. `, approved` is appended when `docs/issue-N/approvals/HEX.md` exists on
   main (already collected by the merged-record loop).
5. Merged-record lines are untouched.

The approval note "Include the worktree-marker fix in scope" is covered by
step 1.

## What did not work

First implementation used the proposal's pattern `refs/heads/issue-*`; the
board printed no branch line at all (same output as before the change).
Evidence 5 shows why; fixed in a follow-up commit with the pattern
`refs/heads/issue-*/*`. The proposal-phase probe had used an unquoted
shell glob, which masked this.
